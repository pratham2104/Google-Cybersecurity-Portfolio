# Sneaker App – PASTA Threat Model

A detailed walkthrough of the **Process of Attack Simulation and Threat Analysis (PASTA)** framework applied to the sneaker company’s new mobile app.

---

## Stage I – Define Business and Security Objectives

**Business objectives identified:**

1. The app must allow **seamless interaction between buyers and sellers**, with easy account creation, login, and secure account management to build user trust.  
2. The company prioritizes **data privacy and responsible handling of sensitive information** (personal data, messages, payment info), ensuring compliance with privacy regulations and maintaining customer confidence.  
3. The app must ensure **secure, reliable, and legally compliant payment processing**, offering multiple payment options, fraud prevention, and transparent transactions that process quickly without errors.  



### Business vs Security Mapping

| **Business**                          | **Security**                                                                 |
|---------------------------------------|-------------------------------------------------------------------------------|
| Seamless buyer-seller transactions    | One account per user; payment flow aligned with PCI-DSS                       |
| User profiles (sign-up, login, manage)| Protected with strong passwords + Multi-Factor Authentication (MFA)          |
| Multiple payment options              | All transactions encrypted (AES for data, PKI for key exchange)               |
| Buyer-seller messaging + rating       | Monitor logs, sanitize input, and prevent abuse of communication channels     |
| Database utilization (listings, users)| Encrypted at rest; role-based access control for admins                       |



### Context Diagram

| **Users**                | **Admins**                  |
|---------------------------|-----------------------------|
| Add sneakers to cart      | Store & update catalogs     |
| Pay for products/service  | Issue invoices              |
| Send inquiry to sellers   | Answer user inquiries       |
| Rate/review a seller      | Moderate reviews/messages   |

## Stage II – Define the Technical Scope

**Technologies used:**  
- API  
- PKI  
- AES  
- SHA-256  
- SQL  

**Detailed evaluation (priority focus):**  
The most critical technology to evaluate first is **SQL**, because the database is central to storing user accounts, sneaker listings, and transaction history. Poor SQL handling presents a direct risk of injection attacks, data theft, or manipulation. While PKI, AES, and SHA-256 are vital for encryption, a compromised database would undermine all other protections.

---

## Stage IV – Threat Analysis

**Internal Threats:**
- **Insider misuse** – a malicious employee abusing elevated database or admin privileges to access sensitive user/payment data.  

**External Threats:**
- **SQL Injection attacks** – attackers exploiting improperly sanitized queries.  
- **Credential and Session Hijacking** – exploiting weak login systems, poor session handling, or unencrypted cookies.  

---

## Stage V – Vulnerability Analysis

**Potential vulnerabilities:**

1. **Database vulnerabilities:**  
   - Lack of prepared statements or secure query handling exposes the app to SQL injection.  
   - Could lead to unauthorized read/write access of sensitive information.  

2. **Weak authentication mechanisms:**  
   - Reliance on simple passwords without MFA.  
   - Exposes users to credential stuffing, brute force, and session hijacking attacks.

**Attack vectors from attack tree:**
- **SQL Injection** → Root cause: no prepared statements or query sanitization.  
- **Session Hijacking** → Root cause: insecure session handling, unencrypted cookies.  
- **Weak Login Credentials** → Root cause: no password policy, no MFA.  

**Impact:** These branches show how attackers can escalate from small weaknesses (weak queries or sessions) to full **user data compromise**.  

---

## Stage VII – Risk Analysis and Impact (Security Controls)

**Recommended security controls to reduce risk:**

1. **Input validation & parameterized queries**  
   - Fully mitigate SQL injection risks.  

2. **Strong authentication policies**  
   - MFA, password complexity rules, and account lockouts.  

3. **Data encryption**  
   - AES for data at rest.  
   - TLS + PKI for data in transit.  

4. **Security monitoring & logging**  
   - SIEM, anomaly detection, and alerting for insider misuse or unusual API activity.  

---

# ✅ Conclusion

By applying the **PASTA framework**, the sneaker app’s security risks can be identified early. Implementing the listed **controls** significantly reduces the chance of incidents like data breaches, credential theft, or fraudulent transactions, ensuring the app is safe to launch with confidence.
