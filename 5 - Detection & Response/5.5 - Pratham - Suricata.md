# Intrusion Detection Systems (IDS) - Suricata
> Please visit this [link](https://www.coursera.org/learn/detection-and-response) for further information.

> **Suricata** is an open-source tool that functions as an intrusion detection system (IDS), intrusion prevention system (IPS), and network analysis platform.

> An **Intrusion Detection System (IDS)** is a software application designed to monitor system activity and identify potential intrusions. IDS tools help organizations track network and system operations to detect any signs of malicious or abnormal behavior.


## Overview

Suricata can operate in three main modes:

1. **Intrusion Detection System (IDS)**:  
   Observes network traffic and generates alerts when suspicious activities or intrusions are detected.  
   In real-world use, it can serve as a *host-based IDS*, monitoring the network and system activity of a single device.

2. **Intrusion Prevention System (IPS)**:  
   Identifies and actively blocks malicious traffic or activity.  
   To use this feature, additional setup is required, such as enabling IPS mode.

3. **Network Security Monitoring (NSM)**:  
   Captures and records network data, including live traffic or packet capture files (full or filtered).  
   This mode is valuable for **incident response**, **digital forensics**, and **testing security rules**.

---

## Signature-Based Detection

Suricata relies on **signature-based detection**, a method that identifies noteworthy events using predefined patterns called signatures.  
Each signature contains three main parts:

1. **Action** – Defines what response to take when a signature match occurs.  
   Common actions include: `alert`, `pass`, `drop`, or `reject`.

2. **Header** – Specifies key details about the network traffic, such as:  
   - Source and destination IP addresses  
   - Source and destination ports  
   - Protocol type  
   - Traffic direction  

3. **Rule Options** – Provide additional customization to refine detection, allowing users to specify conditions and parameters that determine how signatures are applied.

## Examine Alerts, Logs, and Rules with Suricata

In this scenario, you are working as a **security analyst** responsible for monitoring network traffic within your organization. Your task involves configuring and using **Suricata** to detect and trigger alerts based on network activity.

You’ll begin by exploring Suricata’s **custom rules**. Next, you’ll run Suricata using one of these rules to generate alerts and review the results in the `fast.log` file. Finally, you’ll analyze additional log details generated in the `eve.json` file.

For this exercise, you are provided with two files—`sample.pcap` and `custom.rules`—which are located in your home directory.

---

### File Descriptions

1. **`sample.pcap`**  
   A packet capture file containing sample network traffic data that you’ll use to test Suricata rules.  
   This allows you to simulate and repeat network monitoring exercises.

2. **`custom.rules`**  
   This file contains a custom rule at the start of the lab.  
   You’ll add more rules here and test them against the network data in the `sample.pcap` file.

3. **`fast.log`**  
   This file stores the alerts generated by Suricata. It starts out empty and records a new alert line each time a rule is successfully triggered while analyzing the `sample.pcap` file.  
   You can find this file in the `/var/log/suricata` directory.  
   Although `fast.log` is a deprecated format, it remains useful for quick checks or quality assurance tasks, even though it’s not recommended for in-depth incident response or threat hunting.

4. **`eve.json`**  
   This is Suricata’s main log file, containing detailed information about triggered alerts and other network events in JSON format.  
   The file is automatically created when Suricata runs and can also be found in `/var/log/suricata`.

---

When you create or modify a rule, you’ll need to test it to confirm that it functions as intended. You can compare the number of alerts in the `fast.log` file after each run to verify whether your custom signatures are being triggered by the network traffic in `sample.pcap`.

## Step-by-step 

1. Examine a custom rule in Suricata.

Use the `cat command` to display the rule in the `custom.rules` file:

<img width="670" height="53" alt="image" src="https://github.com/user-attachments/assets/dd00af0b-7392-4827-906e-1f7ac39a5542" />

```
alert http $HOME_NET any -> $EXTERNAL_NET any (msg:"GET on wire"; flow:established,to_server; content:"GET"; http_method; sid:12345; rev:3;)
```

* Action
`Alert` : Instructs to alert on selected network traffic. The IDS will inspect the traffic packets and send out an alert in case it matches. 

* Header
`http`: The rule that applies is only to HTTP traffic. The arrow indicates the direction of the traffic from $HOME_NET and going to the destination IP address $EXTERNAL_NET. In this scenario, $HOME_NET is a suricata variable defined in `/etc/suricata/suricata/yaml` as a rule definitions.
$HOME_NET is definatd as the `172.21.224/0/20` subnet. 

* Rule options
`Rule`: Customize signatures with additional parameters.
  * The `msg`: The alert will print out the text `GET on wire`.
  * The `flow:established, to_server`: Determines that packet from the client to the server should be matched (The handshakes: SYN-ACK packet).
  * The `content`: "GET" tells Suricata to look for the word GET in the `http.method` of the packet.
  * The `sid:12345`: Unique numerical value that identify the rule.
  * The `rev:3` indicates the signature's version which is used to identify the signature's version.  

2. Trigger a custom rule in Suricata.

* List the files in the `/var/log/suricata` folder: `ls -l /var/log/suricata`. Up this task, there will be no files to be found. 
```
ls -l /var/log/suricata
```
<img width="668" height="31" alt="image" src="https://github.com/user-attachments/assets/feb6f59c-e9a3-45af-b09f-1b1fcf6027fc" />

* We run Suricata using the `custom.rules` and `sample.pcap`: `sudo suricata -r sample.pcap -S custom.rules -k none`.
  * The `-r sample.pcap` option specifies an input file to mimic network traffic. In this case, the sample.pcap file.
  * The `-S custom.rules` option instructs Suricata to use the rules defined in the custom.rules file.
  * The `-k none` option instructs Suricata to disable all checksum checks.
