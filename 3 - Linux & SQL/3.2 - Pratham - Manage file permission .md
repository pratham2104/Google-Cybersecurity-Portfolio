# Scenario
You are a security professional at a large organization. You mainly work with their research team. Part of your job is to ensure users on this team are authorized with the appropriate permissions. This helps keep the system secure. 

Your task is to examine existing permissions on the file system. You’ll need to determine if the permissions match the authorization that should be given. If they do not match, you’ll need to modify the permissions to authorize the appropriate users and remove any unauthorized access.

# Project description

The research team stores its work under `/home/researcher2/projects`. My task was to confirm that every file and folder grants only the intended access and to correct anything that violated policy. I inspected current permissions, explained how to read the permission string, removed unauthorized write access, secured a hidden archive, and locked down a private **drafts** folder. 

Refer to the [Link](https://github.com/user-attachments/files/21596315/Current.file.permissions.docx), this document displays the file structure of the /home/researcher2/projects directory and the permissions of the files and subdirectory it contains.

## Check file and directory details

**Command used** to list everything including hidden files and to show the long format:
`ls -la /home/researcher2/projects`

**Permissions before changes**

| Item               | Permission string |
| ------------------ | ----------------- |
| project\_k.txt     | `-rw-rw-rw-`      |
| project\_m.txt     | `-rw-r-----`      |
| project\_r.txt     | `-rw-rw-r--`      |
| project\_t.txt     | `-rw-rw-r--`      |
| .project\_x.txt    | `-rw--w----`      |
| drafts (directory) | `drwx--x---`      |

The first character shows the type (`d` for directory or `-` for file); the next nine characters appear in three groups that represent owner, group, and others (read `r`, write `w`, execute `x`).

---

## Describe the permissions string

Example string: **`-rw-rw-r--`**

* First character `-` Regular file
* Characters 2 to 4 `rw-` Owner can read and write
* Characters 5 to 7 `rw-` Group can read and write
* Characters 8 to 10 `r--` Others can read only

Reading left to right tells exactly who may read, write, or execute the file.

---

## Change file permissions

*Issue found* 

Policy does not allow write access for **Others** on any file. `project_k.txt` had (`-rw-rw-rw-`), which gives others write permission.  

*Command used* 

`chmod o-w /home/researcher2/projects/project_k.txt`

*Result check* 

`project_k.txt` now shows `-rw-rw-r--`, eliminating write rights for others and keeps owner and group unchanged.

---

## Change permissions on the hidden file

Requirement: 

The archived hidden file `.project_x.txt` should have no write permission for anyone. Owner and group should be able to read. Others should have no access.  

*Command used* 

`chmod 440 /home/researcher2/projects/.project_x.txt`

*Result check* 

`.project_x.txt` now shows `-r--r-----` which satisfies read for owner, read for group, and no permission for others with no write anywhere.

---

## Change directory permissions

*Requirement* 

Only **researcher2** may access the **drafts** directory.

*Command used* 

`chmod 700 /home/researcher2/projects/drafts`

*Result* 

`drafts` now shows `drwx------` so only the owner can list, read, and enter that folder.



---

## Summary

Using `ls -la`, I reviewed current permissions on all files—including the hidden archive—and explained how to interpret the ten-character permission string. I then:

1. Removed public write access from **project\_k.txt**.
2. Converted **.project\_x.txt** into a read-only archive for owner and group.
3. Restricted the **drafts** folder to the owner only.

These updates align the **projects** directory with organizational authorization policy and minimize the risk of unauthorized modification or access.
