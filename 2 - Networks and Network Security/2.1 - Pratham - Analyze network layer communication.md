## Scenario

As a cybersecurity analyst for an IT consulting company, you are contacted by several customers reporting that they are unable to access the company’s website: www.yummyrecipesforme.com. When they attempt to visit the site, the page fails to load, and a “destination port unreachable” error is displayed. You attempt to replicate the issue and experience the same failure.

To investigate, you launch a network packet capture tool (tcpdump) and try to access the website again. The tool logs show multiple outbound DNS queries using UDP to port 53 on the DNS server at 203.0.113.2, attempting to resolve the domain name. However, every time, the DNS server responds with an ICMP error message: "udp port 53 unreachable."

This indicates that the system attempting to make DNS queries (192.51.100.15) is not receiving valid responses from the DNS server, which prevents the browser from translating the domain name into an IP address, resulting in a failure to load the site.

### In the tcpdump log, you can observe the following:

1. **The first two lines** show that your computer sent a DNS query to the DNS server for the domain **yummyrecipesforme.com**. This request was transmitted using the **UDP protocol**.

2. **The third and fourth lines** display the response from the DNS server in the form of **ICMP packets**. These messages indicate that **port 53**, used for DNS, is unreachable—meaning the DNS server couldn't process the request.

3. **Each entry begins with a timestamp**, such as **13:24:32.192571**, which marks the exact time the event occurred—**1:24 PM and 32.192571 seconds**.

4. **The structure of IP addresses in the log** shows the communication flow: for example, `192.51.100.15 > 203.0.113.2.domain` indicates your computer (source) sent the packet to the DNS server (destination). In the ICMP response, the direction is reversed.

5. **Following the IP addresses**, you’ll find technical details such as **protocols, port numbers, and query identifiers**. One such ID is **35084**, with a “+” symbol showing additional DNS flags. The **"A?"** indicates a request for an A-record, used to resolve a domain to an IP address. The protocol of the response is clearly **ICMP**, followed by an error.

6. **The error message `"udp port 53 unreachable"`** confirms that the DNS service was not accessible. Since port 53 is critical for DNS traffic, this prevented the query from being resolved, blocking access to the website.

7. **Additional lines in the log** repeat the same pattern of failed requests, showing that multiple attempts were made but none succeeded—all received identical ICMP unreachable responses.



> Now that you have captured data packets using a network analyzer tool, it is your job to identify which **network protocol** (UDP) and **network service** (DNS) were impacted by this incident. Then, you will need to write a follow-up report based on your findings.

## Part 1: Provide a Summary of the Problem Found in the DNS and ICMP Traffic Log

- **Protocols used:** The analysis shows that **UDP** was used to send DNS A-record queries from the client **192.51.100.15** to the DNS server **203.0.113.2** on **port 53**. In response, the DNS server returned **ICMP Type 3, Code 3** messages.

- **Log behavior:** Each query was followed by the ICMP error **“udp port 53 unreachable”**, confirming that the DNS server did not process the request. This suggests the DNS service was unavailable or the port was blocked.

- **Timestamp evidence:** The issue was first logged at **13:24:32**, with multiple repeated failures afterward, showing a consistent DNS resolution problem.

- **Interpretation of flags:** The outgoing messages included a query ID and the **“A?”** flag, confirming proper A-record requests for name resolution.

- **Conclusion:** Since **port 53** is essential for DNS queries, and all responses indicated failure, the DNS server is likely down, unreachable, or blocked by a firewall.
