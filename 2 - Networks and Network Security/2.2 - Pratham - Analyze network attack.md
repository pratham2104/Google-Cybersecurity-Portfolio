## Scenario

You are working as a security analyst at a travel agency that relies on its website to advertise travel deals and vacation offers. Employees use this site routinely to browse and recommend packages to clients.

On a particular afternoon, your monitoring system issues an alert indicating a critical issue with the web server. When you attempt to access the site, you are met with a **connection timeout** error in your browser. To investigate, you deploy a packet sniffer to examine the network traffic. You observe a flood of TCP SYN packets originating from an unfamiliar IP address. The traffic volume is overwhelming the server, causing it to fail in responding to legitimate requests—an indication that a potential cyberattack is underway.

You respond by taking the server offline temporarily, allowing it to stabilize, and you configure the firewall to block the IP address responsible for the suspicious activity. While this action helps temporarily, you understand that attackers may use IP spoofing to bypass this block.

You now need to notify your manager, explaining the nature of the attack, how it disrupted services, and what steps should be taken to prevent similar issues in the future.

## Section 1: Identify the type of attack that may have caused this network interruption

**One potential explanation for the website's connection timeout error message is:**  
The web server was overwhelmed by a flood of SYN packets coming from a single unfamiliar IP address (`203.0.113.0`), causing it to fail to complete TCP handshakes with legitimate clients.

**The logs show that:**  
After a few normal connections, the log is flooded with repeated TCP SYN packets from `203.0.113.0` targeting the web server at `192.0.2.1` on port `443`. These requests lack the final ACK step of the TCP handshake, leaving connections half-open and exhausting server resources. By log entry **73 (6.230548 seconds)**, the server begins to send `RST` and timeout responses to legitimate users, indicating it can no longer handle requests.

**This event could be:**  
A **SYN flood attack**, which is a type of **Denial of Service (DoS)** attack. This particular SYN flood is a **direct DoS**, not a **Distributed Denial of Service (DDoS)**, because the attack originates from a single IP address rather than multiple sources.

## Section 2: Explain how the attack is causing the website to malfunction

When a user connects to a website over TCP, the following steps occur in a process called the **three-way handshake**:

1. The client sends a `SYN` packet to initiate the connection.  
2. The server responds with a `SYN-ACK` packet to acknowledge the request.  
3. The client then replies with an `ACK` packet, completing the connection.

In a SYN flood attack, the malicious actor sends a massive number of `SYN` packets but deliberately **does not complete** the handshake by sending the final `ACK`. This causes the server to **reserve system resources** for each half-open connection, which it waits to complete. Over time, the server's resources become maxed out.

The Wireshark log shows exactly this behavior—starting from around **3.390692 seconds** into the log, the server receives SYN packets from `203.0.113.0`, and the frequency of these requests rapidly increases. By **6.230548 seconds**, legitimate requests start failing, and the server returns `RST` or timeout responses, showing that it is overwhelmed.

### Impact on the Organization

- Legitimate users and employees cannot access the sales webpage.  
- Critical business operations, such as vacation bookings and promotions, are disrupted.  
- The website’s downtime may result in revenue loss and customer dissatisfaction.

### Suggested Mitigations

- **SYN Cookies**: Delay resource allocation until the handshake is complete.  
- **Rate Limiting**: Throttle excessive SYN requests at the firewall or server level.  
- **Intrusion Prevention Systems (IPS)**: Detect and block SYN flood patterns.  
- **Load Balancers**: Distribute traffic and absorb spikes in demand.  
- **DDoS Protection Services**: Use external services to filter out attack traffic before it reaches the server.
