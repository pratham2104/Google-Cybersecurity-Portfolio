## Scenario

You serve as a cybersecurity analyst at **yummyrecipesforme.com**, a platform known for selling cookbooks and exclusive recipes. A former employee, dissatisfied and acting maliciously, compromised the company’s website by exposing its best-selling recipes to the public. This individual launched a **brute force attack** targeting the site’s hosting platform. By systematically attempting a variety of default passwords, the attacker eventually succeeded in accessing the administrative account. Upon logging into the backend, they modified the webpage’s source code by inserting a **JavaScript snippet** that tricked users into downloading a file.

Once executed by users, the file redirected their web browsers to a counterfeit website, **greatrecipesforme.com**, where the premium recipes were freely distributed. Within hours of this event, several users contacted the support team. They mentioned being prompted to download what was labeled a browser update file. Post-download, not only did their systems become sluggish, but the website’s address changed unexpectedly. The site’s owner, unable to access the administrative dashboard due to password changes, escalated the matter to the hosting provider. As part of the cybersecurity response team, you were assigned to examine the incident.

In a controlled test environment (sandbox), you replicated the scenario. By navigating to the website and permitting the file to download and run, you witnessed the redirection firsthand. The fake website resembled the original site but offered previously protected content for free.

The **sequence of events**, as revealed by tcpdump traffic analysis, is as follows:

1. A DNS lookup was initiated for `yummyrecipesforme.com`
2. The correct IP address was returned
3. The browser used HTTP to request the original page
4. The system initiated a download for a malicious file
5. A new DNS lookup was made for `greatrecipesforme.com`
6. The new IP address was retrieved
7. HTTP was again used to request the fake page

Further source code analysis confirmed that the website was tampered with, and the JavaScript redirection was embedded by the attacker.

## Section 1: Identify the Network Protocol Involved in the Incident

The main network protocols identified during the investigation were:

- **DNS (Domain Name System)** – Used for resolving domain names (`yummyrecipesforme.com`, `greatrecipesforme.com`) to IP addresses.
- **HTTP (Hypertext Transfer Protocol)** – Used for communication between the browser and the web servers over port **80**.
- **TCP (Transmission Control Protocol)** – Used to establish and maintain connections between the client and server.

---

## Section 2: Document the Incident

At approximately **14:18**, a user visiting the website `yummyrecipesforme.com` initiated a **DNS request** to resolve the domain name to its IP address. The DNS server responded with **203.0.113.22**.

Immediately after, the user’s machine attempted a **TCP handshake** with the web server on port **80**, followed by an **HTTP GET request** for the homepage. This exchange established that the connection to the server was successful.

Upon page load, a **JavaScript function embedded in the website’s source code** prompted the user to download an executable file, claiming it was required to update the browser. The user proceeded to download and run the file.

Following execution, another **DNS request** was sent, this time resolving `greatrecipesforme.com`, which returned the IP address **192.0.2.17**. The user was then redirected via **HTTP** to that domain, which hosted **malware** and was not affiliated with the legitimate website.

A senior analyst later confirmed that the legitimate website's source code had been altered. The root cause was a **brute force attack** that successfully accessed the admin panel using a known default password. Once inside, the attacker:

- Injected malicious JavaScript code to prompt downloads.
- Uploaded a malicious executable that triggered redirection to the spoofed site.
- Changed the admin password to lock out the legitimate owner.

The attack went unnoticed for **several hours**, during which users began submitting complaints to the helpdesk. They reported redirection, slow computer performance, and suspicion of malware infection.

The incident was verified using **tcpdump logs** and **sandbox testing**, which replicated the redirection and download process.

**Key Evidence:**

- HTTP GET request at **14:18:36** to `yummyrecipesforme.com` initiated the download.
- DNS and HTTP redirection to `greatrecipesforme.com` began at **14:20:32**.
- Log entries confirmed connection to the spoofed site and active communication over port 80.

## Section 3: Recommend One Remediation for Brute Force Attacks

**Recommendation:** Implement **Two-Factor Authentication (2FA)** for Admin Panel Access

Two-Factor Authentication significantly increases login security by requiring a second form of verification (such as a code sent via SMS or email) in addition to the password. Even if an attacker successfully guesses or obtains the admin password, they will be **unable to gain access** without the second authentication factor.

### Why This is Effective:

- Prevents unauthorized access even when passwords are weak or compromised.
- Adds a layer of protection against brute force and credential stuffing attacks.
- Commonly used across industries to secure administrative access.

### Additional Suggestions (not required but beneficial):

- Enforce **strong password policies**
- Monitor **failed login attempts** and lock accounts after multiple failures
- Periodically **audit admin credentials** for strength and reuse
